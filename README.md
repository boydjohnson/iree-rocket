# rocket-schema

Canonical FlatBuffers schemas for executable data shared by:

- `rocket-compiler-plugin`, which serializes Rocket executables in C++.
- `iree-rocket-hal` and `rocket-hal-driver`, which verify and consume them
  in Rust.

The source of truth is
[`schema/rocket_executable_def.fbs`](schema/rocket_executable_def.fbs).
The Rust binding is checked in and exported by this repository's
`rocket-schema` crate. This keeps Cargo and cross builds independent of a
host-installed `flatc`. FlatCC C bindings remain build artifacts generated by
the compiler consumer.

## Format

`rocket_executable_def.fbs` defines an `RKT1` FlatBuffer. Its root contains
exports in IREE executable ordinal order. Each export has a name and a typed
kernel definition. Version 1 supports standard and depthwise 2-D convolution.

The convolution fields intentionally mirror the current Rust `ConvShape`.
FlatBuffers verifies the wire structure. The Rocket runtime must still reject
unsupported dimensions, invalid scale combinations, and other hardware
constraints before constructing register commands.

IREE executable binaries add a 64-byte `iree_flatbuffer_file_header_t` before
the FlatBuffer. Both the outer header magic and the inner FlatBuffer file
identifier are `RKT1`; the outer header version is `0`.

See [`docs/compatibility.md`](docs/compatibility.md) for the compatibility
policy and migration contract.

## Generate bindings

FlatCC C bindings, used from the C++ compiler target:

```sh
make generate-c FLATCC=/path/to/iree-flatcc-cli
```

Rust bindings (regenerate the checked-in binding with FlatBuffers 2.0.8):

```sh
make generate-rust FLATC=/path/to/flatc
```

Both commands write beneath `generated/`. The Rust crate pins its runtime to
FlatBuffers 2.0.0, which matches the generated API from `flatc` 2.0.8. Commit
changes to `generated/rust` whenever the schema changes.

To parse a compiler-produced executable in the IREE HAL driver:

1. Call `iree_hal_read_executable_flatbuffer_header` with `RKT1`.
2. Verify the remaining bytes as an `ExecutableDef` root.
3. Require the export count to match the IREE executable layout.
4. Select the export by ordinal and require `KernelDef::Conv2DDef`.
5. Map the table to `ConvShape` and run the existing semantic validation.

The compiler should build the FlatBuffer with IREE's `FlatbufferBuilder` and
emit it using:

```cpp
builder.getHeaderPrefixedBufferAttr(
    context, iree_hal_rocket_ExecutableDef_file_identifier,
    /*version=*/0);
```

The HAL executable format string should change when migrating from the current
manual 85-byte format, for example from `rocket-conv2d-v1` to
`rocket-flatbuffer-v1`.

## Rust

Consumers can use the generated verifier and accessors through:

```toml
rocket-schema = { path = "../rocket-schema" }
```

```rust
use rocket_schema::rocket;
```

`testdata/mnv2_conv0.rkt1` is a compiler-produced golden fixture containing
the 64-byte IREE executable header and one `RKT1` FlatBuffer.
