# Rust bindings

Two crates over `libiree_rocket_runtime.so`, the library [`rocket-runtime`](..)
packages:

- **`rocket-runtime-sys`:** raw bindings, generated by bindgen at build time
  from the installed package's own headers. IREE has no stable C ABI across
  releases, so those headers are the only ones that describe the library.
- **`rocket-runtime`:** the safe wrapper. A `Session` holds the NPU and the CPU
  as one device group, which every rocket-compiler module needs.

```rust
use rocket_runtime::{BufferView, Instance, Session, SessionOptions};

let instance = Instance::new()?;
let mut session = Session::new(&instance, &SessionOptions::default())?;
session.load_module_file("mobilenet_v2.fp16.npu.vmfb")?;

let pixels: Vec<half::f16> = load_image();               // `half` feature
let input = BufferView::from_slice(&session, &[1, 3, 224, 224], &pixels)?;
let logits = session.call("module.main_graph", &[&input])?[0].to_vec::<half::f16>()?;
```

| | |
|---|---|
| `Instance` | the IREE runtime instance, every driver registered; one per process, `Send + Sync` |
| `Session`, `SessionOptions` | the device group and loaded modules. `Devices::CpuOnly` runs `--no-offload` modules without an NPU. `CpuPlacement` picks the CPU workers' cores (default: the fastest cluster). `Send`, not `Sync`: one thread at a time, like IREE's contexts |
| `Function` | a resolved function with reusable argument lists, for calling it repeatedly |
| `BufferView` | a tensor: `from_slice` / `from_bytes` in, `to_vec` / `to_bytes` out, `shape`, `element_type` |
| `Element` | `f32 f64 i8..i64 u8..u64`, and `half::f16` / `half::bf16` with the `half` feature. MLIR integers are signless, so `i8` and `u8` slices are created as `Int8` |
| `Error` | IREE's code plus its fully formatted status: message, source location and annotations |
| `sys` | the raw bindings, for anything not wrapped |

## Building

The crates find the package at build time, in this order:

1. **`ROCKET_RUNTIME_DIR`:** the prefix of an unpacked package (the directory
   holding `include/` and `lib/`). This is the simplest choice for
   cross-compiling.
2. **pkg-config's `iree-rocket-runtime`:** set `PKG_CONFIG_ALLOW_CROSS=1` when
   cross-compiling.

The directory is its own Cargo workspace, excluded from the repository's root
workspace, because the root's `cargo test --workspace` (and `ci.yml`) has no
package to build against. Bindgen needs libclang, like the rest of the repo.

```sh
# On the board's architecture, against the nightly's iree-rocket-runtime-aarch64:
ROCKET_RUNTIME_DIR=/path/to/iree-rocket-runtime-aarch64 \
CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER=aarch64-linux-gnu-gcc \
  cargo build --release --target aarch64-unknown-linux-gnu --example run

# Tests run anywhere, CPU-only, against a host build of the package:
cmake --install iree-build/host/build --component IreeRocketRuntime --prefix /tmp/pkg
ROCKET_RUNTIME_DIR=/tmp/pkg cargo test --features half
```

Linking is dynamic only. The package's static archive carries the Rocket
driver's own copy of the Rust standard library, which would collide with yours.
Ship `libiree_rocket_runtime.so.<N>` (`.so.314` for IREE 3.14) beside your binary, with an `$ORIGIN` rpath,
or on the loader path. This crate's own tests and examples get an rpath to the
package automatically.

## Tests and the example

- **`tests/cpu_only.rs`:** the wrapper end to end on the CPU device. It uses a
  VMVX fixture (`tests/data/cpu_ops.mlir`; regenerate the `.vmfb` after an IREE
  bump with the command in that file), so the same test binary runs on x86 and
  on the board. Its one NPU test expects session creation to succeed where the
  `rocket` driver has NPU cores bound, and a clean `Unavailable` elsewhere.
- **`examples/run.rs`:** the counterpart of `iree-run-module`. It takes
  `SHAPExTYPE=@input.bin` inputs, and `--output-dir` writes each result's raw
  bytes, which you can `cmp` against `iree-run-module --output=@ref.bin`.

Verified 2026-11-27 on the board (7.3.6, patched `rocket.ko`, 600 MHz):

- All 15 tests pass there and on x86.
- With a random f16 input, `run` writes byte-identical results to
  `iree-run-module`:
  - MobileNetV2 fp16: 9.4 ms per call over 19 calls;
  - ViT-B/16 fp16: 189 ms.
